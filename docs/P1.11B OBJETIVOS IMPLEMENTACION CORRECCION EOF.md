# P1.11B - Implementación Corrección EOF Guard Band (Dropout)

Lee primero:

* docs/CURRENT_STATE.md
* docs/P1.11A REPORTE DE AUDITORÍA EOF vs DROPOUT.md

## Contexto

La auditoría P1.11A confirmó que el falso positivo persistente:

```text
[VOS-33] Dropout | 101.647s
```

es generado por la lógica residual de EOF dentro de:

```rust
if inside_dropout {
    ...
}
```

en `detectar_dropouts()`.

La hipótesis EOF quedó confirmada con evidencia matemática.

Sin embargo, NO implementaremos la eliminación completa del bloque EOF.

Queremos una solución más conservadora que preserve la capacidad futura del detector para reportar dropouts abiertos legítimos.

---

# Objetivo

Implementar una zona de seguridad (EOF Guard Band) para impedir que la terminación natural del archivo sea interpretada como un Dropout.

No modificar:

* Umbrales RMS
* Sensibilidad
* ScanParams
* LPC
* STFT
* Detectores distintos a Dropout

---

# Diseño Aprobado

Mantener intacto el bloque:

```rust
if inside_dropout {
    ...
}
```

pero agregar una condición previa.

Conceptualmente:

```rust
samples_to_eof = n_samples - start_idx
```

Si el supuesto dropout comienza demasiado cerca del final físico del archivo:

```text
≤ 150 ms antes de EOF
```

no debe reportarse.

Justificación:

* P1.11A confirmó que no existen dropouts legítimos documentados que terminen exactamente en EOF.
* El evento no es reparable por ausencia de muestras posteriores.
* Preserva la arquitectura actual.
* Evita eliminar funcionalidad potencialmente útil.

---

# Implementación

Determinar la cantidad exacta de muestras equivalentes a:

```text
150 ms
```

usando el sample rate correspondiente.

Aplicar la validación únicamente dentro del bloque EOF.

No modificar la lógica principal del bucle de detección.

No modificar:

```rust
inside_dropout = true
```

No modificar:

```rust
inside_dropout = false
```

No modificar los eventos que sí se recuperan dentro del archivo.
