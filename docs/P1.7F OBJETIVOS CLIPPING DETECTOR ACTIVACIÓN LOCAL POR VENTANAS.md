# VOSTOK DSP LAB - P1.7F

  # CLIPPING DETECTOR - ACTIVACIÓN LOCAL POR VENTANAS

  Contexto:

  La auditoría forense posterior a P1.7E reveló dos hallazgos críticos:

  ## Hallazgo 1

  Los eventos de clipping reales continúan siendo omitidos:

  GT-008
  34.532s -> 34.780s

  GT-013
  54.607s -> 54.893s

  A pesar de:

  * generador corregido (P1.6B)
  * detector habilitado en UI (P1.7E)
  * activación híbrida (P1.7B)

  ## Hallazgo 2

  La activación híbrida actual sigue calculando:

  ```rust
  local_peak = max(samples)
  ```

  sobre el archivo completo.

  Si existe un click a 1.0 en cualquier parte del audio:

  ```rust
  limit = max(0.70, 1.0 * 0.95)
  limit = 0.95
  ```

  para los 101 segundos completos.

  Esto impide detectar clipping real con picos de:

  * 0.8211
  * 0.7863

  aunque posean flat-tops válidos.

  ---

  OBJETIVO

  Corregir exclusivamente la lógica de activación del detector de clipping.

  NO modificar:

  * benchmark
  * evaluador
  * matching
  * frontend
  * consolidación
  * geometría de flat-tops
  * tolerance
  * count >= 2

  La lógica geométrica actual debe permanecer intacta.

  ---

  IMPLEMENTACIÓN

  ## 1. Activación por ventanas locales

  Sustituir el cálculo:

  ```rust
  local_peak = peak_archivo_completo
  ```

  por:

  ```rust
  local_peak = peak_ventana_actual
  ```

  La detección debe operar sobre ventanas temporales independientes.

  Ventana sugerida:

  1 segundo

  Ejemplo:

  44100 muestras @ 44.1 kHz

  ---

  ## 2. Umbral híbrido por ventana

  Mantener la filosofía:

  ```rust
  limit = max(
      piso_absoluto,
      local_peak * factor
  )
  ```

  pero calculada para cada ventana.

  Ejemplo:

  Ventana A:
  peak = 0.82

  limit ≈ 0.78

  Ventana B:
  peak = 1.00

  limit ≈ 0.95

  ---

  ## 3. Mantener detector geométrico

  NO tocar:

  ```rust
  tolerance
  count >= 2
  flat-top detection
  ```

  El objetivo es únicamente permitir que los candidatos lleguen a esa etapa.
