  ### 2. Explicación DSP: Click vs Clipping

  El error fundamental del generador anterior era tratar la  longitud  (1 a 3 muestras) como la "duración de un scratch de vinilo". Al asignar
  repetidamente el mismo valor máximo ( val = ±1.0 ) a muestras contiguas ( audio[inicio:inicio + longitud] = val ), se estaba creando
  sintéticamente Corriente Continua (DC) en miniatura.

  • Matemática del Clipping (Rust): Saturación donde  count >= 2  muestras permanecen planas ( diff <= tolerance ).
  • Matemática del Click Real: Una discontinuidad de banda ancha equivalente a un Impulso de Dirac ( δ(t) ). Altera radicalmente el valor de una
  muestra e inmediatamente la señal intenta retornar a su curso, creando una derivada altísima pero nunca sosteniendo la meseta.

  Al limitar  longitud = 1 , garantizamos que el salto sea puramente impulsivo, cargado de alta frecuencia, que romperá el modelo LPC (siendo
  detectado por  detectar_clicks() ) pero sin invadir jamás el territorio geométrico del detector de Clipping.

  ### 5. Riesgos Conocidos

  1. Disminución artificial en Precision de Distortion: Como el benchmark antiguo creaba cientos de Clicks con flat-top (GT-008, GT-013, etc.),
  el detector de Rust acertaba legítimamente en marcarlos como Distortion. Al correr de nuevo el evaluador con el audio recién generado, el
  Recall de Clicks debería subir al ~90%+, pero es crucial re-correr el backend de Rust sobre este nuevo  .wav  para que el orquestador deje de
  cruzar cables entre ambas métricas.
  2. Vinyl Scratch Modeling: Si en el futuro se desea simular un "arañazo" grueso de vinilo que dure varios milisegundos, no debe construirse
  inyectando corriente continua ( val ). Debería diseñarse inyectando ruido blanco de alta amplitud con una envolvente muy estrecha, de modo que
  la onda sea ruidosa y caótica en vez de plana.
