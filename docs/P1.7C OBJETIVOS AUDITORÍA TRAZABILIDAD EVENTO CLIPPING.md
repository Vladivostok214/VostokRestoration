# VOSTOK DSP LAB - P1.7C

  # AUDITORÍA DE TRAZABILIDAD DEL EVENTO CLIPPING

  Contexto:

  Durante la auditoría P1.7A se confirmó que el detector de clipping sí encuentra candidatos válidos cuando el umbral de activación es corregido.

  Durante P1.7B se comprobó matemáticamente que:

  GT-008:

  * Entra al detector.
  * Genera 34 regiones candidatas.
  * Posee flat-tops válidos.

  GT-013:

  * Entra al detector.
  * Genera 73 regiones candidatas.
  * Posee flat-tops válidos.

  Sin embargo, los benchmarks continúan reportando:

  Clipping:

  * TP = 0
  * FP = 0
  * FN = 2

  Además, se detectó una posible inconsistencia arquitectónica:

  En types.rs existe:

  ```rust
  pub enum GlitchType {
      Click,
      Pop,
      Dropout,
      Hum,
      Hiss,
      Slip,
      Distortion,
  }
  ```

  pero no existe explícitamente:

  ```rust
  Clipping
  ```

  Mientras que:

  * El Ground Truth utiliza "clipping"
  * El benchmark utiliza "clipping"
  * Los reportes utilizan "clipping"

  Existe la posibilidad de que el detector genere eventos correctamente pero éstos se pierdan o reclasifiquen durante el pipeline.

  ---

  OBJETIVO

  Realizar una auditoría completa de trazabilidad.

  Seguir un evento generado por detectar_clipping() desde su creación hasta el reporte final.

  Determinar si existe una ruptura de mapeo entre:

  Backend DSP
  ↓
  GlitchType
  ↓
  Serialización JSON
  ↓
  IPC Tauri
  ↓
  Frontend React
  ↓
  Reporte TXT
  ↓
  Benchmark Matcher
