REPORTE TÉCNICO: AUDITORÍA DE FLUJO SCANPARAMS (P1.7D)

  ### 1. Localización de referencias a  distortion

  El término viaja exclusivamente a través de los siguientes archivos en la UI:

  •  src/hooks/useGlitchManager.js  (Línea 89): Define el estado inicial de  scanParams  con  distortion: false .
  •  src/components/VostokRestoration.jsx : Lo lee pasivamente para colorear ( color = '#FF003C' ) o para renderizar el Inspector ( type ===
  'distortion' ). No existe ningún  input  ni botón atado a él.
  •  src/components/SpectrogramGL.jsx : Lo etiqueta dinámicamente como  CLIP  en los overlays visuales.

  ### 2. Trazabilidad del Flujo ( ScanParams )

  El flujo viaja de esta manera al presionar el botón "Re-Analizar Audio":

  1. React State ( useGlitchManager.js ): El estado  scanParams  reside en memoria de React.
  2. Llamada Tauri: Se ejecuta la función  scanAudio() .
  3. Tauri IPC ( lib.rs ): La función asíncrona serializa el objeto JSON y lo pasa al comando  #[tauri::command] fn ejecutar_analisis_avanzado .
  4. Core DSP ( detectors.rs ): El backend de Rust deserializa el JSON dentro del struct  ScanParams  y orquesta los hilos de CPU.

  ### 3. Payload Real Enviado

  La llamada exacta que se hace por debajo de la interfaz ( invoke ) manda el siguiente payload estático:

    {
      clicks: true,       // Visible en UI (Checkbox)
      hum: true,          // Visible en UI (Checkbox)
      hiss: false,        // Visible en UI (Checkbox)
      dropouts: true,     // Visible en UI (Checkbox)
      distortion: false,  // <--- OCULTO Y SIEMPRE FALSE
      sensitivity: 0.0,   // Modificado en el benchmark P1.5
      audio_mode: "voice" // Modificado en el benchmark P1.5
    }

  ### 4. ¿Existe algún Override o Activación Oculta?

  NO. Busqué todos los  setScanParams  en el frontend. Las únicas propiedades que la interfaz modifica dinámicamente son  clicks ,  hum ,  hiss ,
  dropouts ,  sensitivity  y  audio_mode . La propiedad  distortion  jamás se actualiza a  true  en ningún escenario.

  ### 5. Auditoría Backend (Rust)

  Cuando el payload llega a  src-tauri/src/vostok_dsp/detectors.rs  (alrededor de la línea 1098 en la orquestación multihilo de
  ejecutar_analisis_dsp_mono ), se ejecuta el siguiente bloque:

    if params.distortion {
        detectar_clipping(&audio.samples, audio.sample_rate)
    } else {
        Vec::new() // Devuelve un vector de anomalías vacío instantáneamente
    }

  Conclusión: Dado que  distortion == false , el comportamiento real es la Opción A (El detector no se ejecuta).

  ### 6. Diagnóstico Final

  La HIPÓTESIS E y la HIPÓTESIS C combinadas son las correctas:

  │ distortion=false . El detector de clipping ni siquiera corrió una sola vez sobre el Ground Truth.
